## 1단계 결과(0.5.6)

- `CIMD_ALLOWED_HOSTS` += `chatgpt.com`(서브도메인 근거가 없어 `.chatgpt.com` 은 넣지 않았다).
- `apps/oauth/cimd.py`: `_build_application_kwargs` 를 감싸, 단수 방식이 `none` 이 아니어도 문서의
  `token_endpoint_auth_methods_supported` 에 `none` 이 있으면 `none` 으로 보고 넘긴다.
  근거 — OpenAI 문서(developers.openai.com/plugins/build/auth): *"ChatGPT selects a method from the intersection of
  those sets."* 허브 메타데이터는 `none` 을 광고하므로 교집합은 `none` 이고 ChatGPT 는 PKCE 공개 클라이언트로
  토큰을 교환한다. `none` 이 목록에 없거나 목록이 아니면 여전히 거부, `client_secret` 금지도 그대로.
- 기동 자체 검사(`install`)에 ChatGPT 표본을 더했다. 감싸기를 걷으면 새 테스트 5건이 실패한다(확인함).
- ChatGPT 의 안정 redirect(`connector_platform_oauth_redirect`)는 RFC 9207 `iss` 를 요구한다 — 허브는 H-3 에서
  `COMPLIANT_BCP_RFC9700_AUTHZ_RESPONSE_ISS` 를 켰다.
- 검증: ruff · format · `check --fail-level WARNING` · 마이그레이션 · pytest **212 passed**(운영 `check --deploy` 0건 포함).
  **공개 HTTPS 왕복 실측은 아직 없다** — 배포 뒤 ChatGPT 웹 커넥터·claude.ai(회귀)로 잰다.

## 2단계 결과 — loopback 콜백(Codex 앱 · Claude Code OAuth)

1단계 직후 Codex 문서는 `invalid_scheme: http://127.0.0.1/callback; … http://localhost/callback` 로 떨어졌다.

- 표준의 경계: RFC 9700 §2.1 은 http redirect 를 금하되 네이티브 앱 loopback 은 예외, RFC 8252 §7.3 은 loopback
  포트를 따지지 말라고 한다. 즉 「https, 또는 loopback 호스트의 http」.
- DOT 는 스킴만 본다(`ALLOWED_REDIRECT_URI_SCHEMES`, 앱별 `get_allowed_schemes()`) — 막거나 전부 열거나 둘뿐이다.
- `localhost` 는 RFC 8252 §8.3 이 권하지 않지만 Codex·Claude Code 가 쓴다 → `ALLOW_LOCALHOST_LOOPBACK=True` 필요.
- 「Claude Code 는 연결 토큰으로 붙으므로 무관」(`hub/settings.py`·`docs/deploy.md`)은 0.4.0 에서 화면 발급 경로를
  없앤 뒤로 맞지 않았다(H-3 「남은 질문 1」 이 예고한 위험) — 정정했다.

**결정: `Application.get_allowed_schemes()` 를 기동 시 감싼다**(`apps/oauth/redirects.py`). 전역 http 허용(이슈의
「단순안」)도, 커스텀 Application 모델 교체도 아니다.

- 판정: 원래 스킴에 `http` 가 없고, 앱의 http redirect 가 **하나 이상 있으며 모두** loopback 호스트(`127.0.0.1`·`::1`,
  `ALLOW_LOCALHOST_LOOPBACK` 이면 `localhost`)일 때만 `http` 를 더한다. https 와 loopback 이 섞인 앱은 허용,
  loopback 과 다른 http 가 섞이면 전부 거부. `127.0.0.1.example.com`·`127.0.0.2` 는 loopback 이 아니다.
- 한 점: 등록 검증 `AbstractApplication.clean`(CIMD·DCR·admin 모두 `full_clean`)과 응답 리디렉트
  `BaseAuthorizationView.redirect` 가 둘 다 이 메서드를 부른다. 기동 자체 검사가 두 함수의 `co_names` 와 표본 5건을 본다.
- 포트 무관 매칭은 DOT `redirect_to_uri_allowed` 가 이미 한다. `ALLOW_LOCALHOST_LOOPBACK=True` 를 켰다(Codex·Claude Code 가
  `localhost` 를 쓴다).
- 동의 화면: 이번 요청의 redirect 가 loopback 이면 경고 띠(「이 컴퓨터의 프로그램으로 돌아갑니다 — 직접 시작한
  연결이 아니면 거부」). 기존 경고 메시지와 같은 클래스라 `just css` 결과는 커밋본과 같다(확인함).
- 테스트 `tests/test_oauth_loopback.py` 17건(전역 https 만으로 덮어쓴 조건): 판정 표 · localhost 설정 의존 ·
  비-loopback 등록 거부 · Codex CIMD 등록 · 비-loopback 이 섞인 CIMD 거부 · **임시 포트(127.0.0.1·localhost)로
  동의 → 302 → PKCE 토큰 교환 200** · 등록 안 된 경로 거부 · https 콜백엔 경고 없음. 브리지를 걷으면 9건 실패(확인함).
- 운영 프로브(`tests/test_production_settings.py`): DCR 로 `http://127.0.0.1:33418/callback`·`http://localhost/callback`
  → 201(전에는 400), `http://hub-callback.example/callback` → 400, `check --deploy` 0건 유지.
- 검증 합계: ruff · format · `check --fail-level WARNING` · 마이그레이션 · pytest 전체 통과.
  **공개 HTTPS 왕복 실측은 아직 없다** — 배포 뒤 Codex 앱 · ChatGPT 웹 커넥터 · Claude Code(헤더 없이 OAuth) ·
  claude.ai(회귀) 순으로 잰다.

## upstream(DOT) 이슈/PR 초안 — 게시는 사용자 결정

### A. loopback 호스트에만 http redirect 허용

**제목**: Allow plain-`http` redirect URIs only for loopback hosts (RFC 8252 §7.3) without opening `http` globally

> `COMPLIANT_BCP_RFC9700_REDIRECT_URI_SCHEME` (E003) forces a choice: drop `http` from `ALLOWED_REDIRECT_URI_SCHEMES`
> and lose native-app loopback callbacks, or keep it and accept `http` redirect URIs on any host. RFC 9700 §2.1 and
> RFC 8252 §7.3 draw the line in between — `http` is acceptable only for loopback redirects. Native MCP clients hit this
> today: Codex (`https://chatgpt.com/oauth/codex/client.json`) and Claude Code register `http://127.0.0.1/callback` /
> `http://localhost/callback`, and CIMD resolution fails in `full_clean()` with `invalid_scheme`.
>
> **Proposal**: a setting `ALLOW_LOOPBACK_HTTP_REDIRECT_URIS` (default `False`). When `True`, an `http` redirect URI is
> accepted if its host is `127.0.0.1` / `::1` (or `localhost` when `ALLOW_LOCALHOST_LOOPBACK`), even though `http` is
> not in `ALLOWED_REDIRECT_URI_SCHEMES`. The E003 gate keeps meaning "no `http` on arbitrary hosts" and stays green.
>
> ```diff
> # oauth2_provider/models.py
> +def is_loopback_redirect_uri(uri):
> +    parsed = urlparse(uri)
> +    loopback = {"127.0.0.1", "::1"}
> +    if oauth2_settings.ALLOW_LOCALHOST_LOOPBACK:
> +        loopback.add("localhost")
> +    return parsed.scheme == "http" and parsed.hostname in loopback
> +
> +def redirect_schemes_for(uri, schemes):
> +    if oauth2_settings.ALLOW_LOOPBACK_HTTP_REDIRECT_URIS and is_loopback_redirect_uri(uri):
> +        return set(schemes) | {"http"}
> +    return set(schemes)
>
>  # AbstractApplication.clean()
>              for uri in redirect_uris:
> +                validator = AllowedURIValidator(redirect_schemes_for(uri, allowed_schemes), ...)
>
> # oauth2_provider/views/base.py — BaseAuthorizationView.redirect()
> -        return OAuth2ResponseRedirect(redirect_to, allowed_schemes)
> +        return OAuth2ResponseRedirect(redirect_to, redirect_schemes_for(redirect_to, allowed_schemes))
> ```
>
> Port matching already treats loopback specially (`redirect_to_uri_allowed`). Tests: `http://127.0.0.1/cb` and
> `http://[::1]/cb` register with `ALLOWED_REDIRECT_URI_SCHEMES=["https"]`; `http://example.com/cb` and
> `http://127.0.0.1.example.com/cb` do not; `localhost` only with `ALLOW_LOCALHOST_LOOPBACK`; authorization succeeds with
> an ephemeral port; E003 stays silent. Happy to open a PR.

### B. CIMD: 단수 인증 방식이 비공개여도 `none` 을 함께 지원하면 공개 클라이언트로

**제목**: CIMD: accept documents whose `token_endpoint_auth_methods_supported` includes `none` (ChatGPT connector)

> ChatGPT's CIMD document (`https://chatgpt.com/oauth/client.json`) declares
> `"token_endpoint_auth_method": "private_key_jwt"` and `"token_endpoint_auth_methods_supported": ["none", "private_key_jwt"]`.
> ChatGPT picks a method from the intersection of that list and the AS metadata's `token_endpoint_auth_methods_supported`
> (OpenAI docs), so against a DOT server advertising `none` it authenticates as a public client. `_build_application_kwargs`
> only reads the singular field and rejects the document. Proposal: when the singular method is not `none` but the plural
> list contains `none`, register the client as public (unchanged otherwise; `client_secret` still forbidden).
> Real `private_key_jwt` support (RFC 7523, `jwks_uri`) would be the larger follow-up.
