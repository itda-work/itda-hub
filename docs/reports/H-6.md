## 2. 설계 판단

### 2.1 `fx` 의 출처를 서울외국환중개 → 한국은행 ECOS 로 바꿨다

카탈로그의 `fx` 행은 출처가 「서울외국환중개」였다. 그쪽은 **공개 API 가 아니라 화면**이다 —
어댑터를 쓰려면 HTML 스크래핑이 되고, 그것은 허브의 「읽기 전용 HTTPS GET, 상류의 계약 위에
선다」 와 다른 종류의 의존이다(마크업이 바뀌면 조용히 틀린 숫자를 낸다).

같은 값(매매기준율)을 **공식 API 로 내는 곳이 한국은행 ECOS** 다. 키가 필요해지지만, 카탈로그의
`credential` 을 `NONE` → `SHARED` 로 올리는 것이 「키 없이 되는 척하다 스크래핑으로 깨지는」
것보다 정직하다. 키 없는 제3자 집계 서비스(ECB 파생 등)도 후보였으나 **한국의 매매기준율이
아니어서** 같은 이름으로 다른 값을 내게 된다 — 택하지 않았다.

### 2.2 같은 SHARED 키를 두 도구가 쓰는 구조 — 괜찮다. 다만 대가가 있다

**브리프가 물은 지점이다. 결론: 이 구조로 둔다.**

- **모델은 이미 이것을 허용한다.** `Tool.shared_value()` 는 `SHARED_<설정 키>` 환경변수를 읽고,
  `credentials.resolve` 는 `ToolboxEntry`(사용자×도구) 단위로 해석한다. 두 도구가 같은
  `setting_key` 를 선언해도 서로의 상태를 보지 않는다 — 공유되는 것은 **환경변수 이름 하나**이지
  DB 행이나 권한이 아니다.
- **도구 행을 합치지 않은 이유는 스코프다.** 스코프가 곧 도구함이라(`tool:fx` 와 `tool:ecos` 는
  따로 담긴다) 행을 합치면 환율만 필요한 사용자에게 통계표 전체가 열린다. 도구 하나에 슬러그
  하나라는 저장소의 불변식(`tests/test_catalog_adapter_contract.py` 의 스코프 유일성)도 지켜진다.
- **대가**: 개인 키를 쓰는 사용자는 같은 ECOS 키를 두 도구에 **각각** 붙여넣어야 한다(도구함 설정이
  `ToolboxEntry` 마다 따로 있으므로). 관리자 공용 키를 쓰면 `SHARED_ECOS_API_KEY` 하나로 둘 다
  열리므로 강의 기본값에서는 드러나지 않는다.
- **키 회전 시 주의**: ECOS 키를 바꾸면 `fx`·`ecos` **둘 다** 영향을 받는다. 공용 키는 환경변수
  하나라 한 번에 바뀌지만, 개인 키는 사용자가 두 곳을 고쳐야 한다. `docs/tool-keys.md` 의 `fx` 절에
  이 사실을 적었다.
- **되돌릴 여지**: 「설정 키가 같은 도구끼리 설정을 공유한다」 를 나중에 도입한다면 `ToolSetting`
  을 `(user, setting_key)` 단위로 올리는 변경이 필요하다. 지금 하지 않는 이유는 그것이
  **도구함의 의미(담은 것만 쓴다)와 설정의 의미(도구마다 따로)를 뒤섞는** 변경이라, 수요가
  드러나기 전에 하면 되돌리기 어렵기 때문이다.

### 2.3 항목코드를 저장소에 박지 않는다

`fx_rate(currency='미국달러')` 는 통화 이름 → 항목코드를 **상류에 묻는다**(`StatisticItemList`).
참고한 스킬의 문서에는 `731Y003` 의 항목코드 표가 있었지만, 그 표를 옮겨 적으면 상류가 항목을
개편했을 때 **조용히 다른 통화**를 돌려준다(오류가 아니라 틀린 값이라 더 나쁘다). 대신 호출이
한 번 늘고(항목 목록 + 시계열), 못 찾으면 `available` 에 고를 수 있는 항목 이름을 함께 낸다.

통계표 코드 `731Y003` 자체는 여전히 상수다 — 이것만은 「어느 표가 환율인가」 라는 도구의 정의라
상류에 물을 수 없다. 라이브 검증에서 가장 먼저 확인할 값이다(§5).

### 2.4 판정은 채널로 — `error_kind` 를 더했다

세 어댑터 모두 `ok`·`error_code` 에 더해 `error_kind` 를 낸다.

| `error_kind` | 뜻 | 부르는 쪽이 할 일 |
|---|---|---|
| `credential` | 키·활용신청 문제 | 허브 설정 화면으로 안내 |
| `argument` | 호출 인자 문제 | 인자를 고쳐 다시 부른다 |
| `transient` | 한도·타임아웃 | 잠시 뒤 재시도 |

**데이터 없음은 실패가 아니다.** data.go.kr `03`(NODATA_ERROR)과 ECOS `INFO-200` 은 `ok: true,
count: 0` 으로 낸다. 오류로 내면 「그 달에 그 지역의 거래가 없었다」 는 **참인 답**이 키 의심으로
둔갑해 사용자가 설정 화면을 헛돈다.

### 2.5 인자 검증을 상류에 미루지 않는다

실거래가 상류는 `LAWD_CD`·`DEAL_YMD` 형식이 틀려도 **빈 결과**를 돌려주는 때가 있다. 그러면
「코드를 잘못 적었다」 와 「거래가 없었다」 가 같은 모양이 된다. 그래서 `lawd_cd`(숫자 5 자리)·
`deal_ymd`(`YYYYMM`)·`deal_type`, ECOS 의 주기 코드·기간 유무를 **상류에 닿기 전에** 막고
`error_code: 'ARGUMENT'` 를 낸다. 테스트가 「상류를 부르지 않았다」 까지 잰다.

### 2.6 전 페이지를 끌어오지 않는다

참고한 스킬은 `totalCount` 까지 페이지를 도는 배치다. 허브에서는 결과가 **모델의 컨텍스트로
통째로** 들어가므로 한 호출이 한 페이지다(`numOfRows` 상한 100, ECOS 행 상한 500). 대신
`total_count`·`page` 를 함께 내 부르는 쪽이 다음 페이지를 고른다.

### 2.7 아파트만, 매매·전월세 둘

상류에는 12 종(8 부동산 유형 × 매매/전월세)이 있으나 이번에는 **아파트 2 종**만 열었다.
`realty.ENDPOINTS` 에 줄을 더하면 늘어나고, 그때 `property_type` 인자가 필요하다. 수요가 확인된
것부터 여는 쪽을 택했다 — 12 종을 한 번에 열면 활용신청을 12 번 해야 실제로 쓸 수 있다.

## 3. 보안 — 경로에 비밀을 싣는 상류(#4 의 확장)

**ECOS 는 인증키를 쿼리 파라미터가 아니라 URL 경로 세그먼트로 받는다**
(`/api/StatisticSearch/<인증키>/json/kr/1/100/...`). #4 의 처방은 「쿼리스트링을 통째로 버린다」
였는데, 그 규약은 여기에 닿지 않는다. 경로를 함께 버릴 수도 없다 — 버리면 어느 엔드포인트가
실패했는지가 사라져 안전한 URL 이 아무 말도 하지 않게 된다.

처방:

- `safe.check(response, source, secret='')` — 그 호출에 **실어 보낸 비밀 값**을 받아
  `UpstreamError.safe_url` 에서 지운다. 「어느 파라미터가 비밀인가」 라는 **이름 목록이 아니라
  값**이라, 새 도구가 목록 갱신을 잊어 새는 경로가 없다(#4 가 피하려던 바로 그 실패 양식).
- `safe.redact` 가 지우는 형태를 둘 → **셋**으로. 원문 · 쿼리 인코딩(`+` 는 `%2B`, 공백은 `+`) ·
  **경로 인코딩**(`quote(safe='')`, 공백은 `%20`). 경로 인코딩 형태는 쿼리 인코딩만 보는 검사를
  그대로 지나간다.
- `tests/test_credential_leak.py` 가 세 형태를 **어댑터 셋 전부**(kosis·ecos·realty)에 대해,
  예외 문자열 · 예외 repr · 성공/실패 로그에서 잰다. 키를 어디에 싣는지가 어댑터마다 달라
  한 어댑터의 통과가 다른 어댑터를 보증하지 않는다.

남은 것(이번에 하지 않음): 상류가 XML 폭탄(billion laughs)을 보내는 경우. `xml.etree` 는 외부
엔티티를 풀지 않지만 내부 엔티티 확장은 막지 않는다. 상류가 data.go.kr 하나이고 응답 본문을
결과에 싣지 않으므로 이번 범위 밖으로 두되, 어댑터가 늘면 `defusedxml` 도입을 검토한다.

## 4. 각 API 의 키 발급처와 신청 절차

전문은 [docs/tool-keys.md](../tool-keys.md) 의 세 절(`realty-deals`·`ecos`·`fx`). 요약:

| | 부동산 실거래가 | 한국은행 경제지표 · 환율 |
|---|---|---|
| 발급처 | [data.go.kr](https://www.data.go.kr/) (공공데이터포털) | [ecos.bok.or.kr/api](https://ecos.bok.or.kr/api/) |
| 가입 | 공공데이터포털 회원 | ECOS 회원 |
| 신청 | **활용신청**을 서비스마다 — 매매([15126469](https://www.data.go.kr/data/15126469/openapi.do))·전월세([15126474](https://www.data.go.kr/data/15126474/openapi.do)) **둘 다** | 인증키 신청(가입 시 자동 부여) |
| 승인 | 자동, 다만 **게이트웨이 동기화 5~30 분** | 즉시 |
| 유효기간 | 활용신청일로부터 2년(연장 가능) | 없음 |
| 키 위치 | 마이페이지 → 데이터활용 → 개발계정 → **일반 인증키(Decoding)** | 마이페이지 / 인증키 관리 |
| 한도 | 개발계정 일 10,000 건 | 과도 호출 시 `ERROR-602` 로 일시 제한 |
| 함정 | **Encoding 값을 넣으면 `30`** — 허브가 스스로 URL 인코딩하므로 이중 인코딩이 된다 | 키 자리에 `sample` 을 넣으면 10 건까지 온다(구조 확인용) |

운영자가 공용 키를 넣을 때: `.env` 에 `SHARED_DATA_GO_KR_API_KEY` · `SHARED_ECOS_API_KEY` 를
채우고 **두 프로세스를 재생성**한다 — `docker compose up -d --force-recreate hub-web hub-mcp`.
키를 읽는 쪽은 `hub-mcp` 이고 담기 가능 여부를 판정하는 쪽은 `hub-web` 이라 한쪽만 띄우면
「담기는데 호출이 거부되는」 상태가 된다(KOSIS 절과 같은 함정).

## 5. 남은 라이브 검증 — 실제 키를 얻은 뒤 할 일

단위 테스트가 고정한 것은 **허브가 상류의 모양을 어떤 판정 채널로 옮기는가**다. 상류가 실제로 그
모양을 내는지는 재지 못한다. 순서대로 확인한다.

1. **키를 넣고 스택을 띄운다.**
   `.env` 에 `SHARED_DATA_GO_KR_API_KEY`·`SHARED_ECOS_API_KEY` → `just up`(또는 위 `--force-recreate`).
2. **도구함을 채우고 토큰을 받는다.**
   `just token admin@example.com --tools weather,kosis,realty-deals,ecos,fx --shared`
3. **왕복 스모크.** `HUB_TOKEN=<토큰> just smoke`
   `scripts/mcp_smoke.py` 가 도구마다 한 번씩 부르고 결과를 `calls` 에 담는다. 각 도구가
   `denied` 가 아니라 `ok: true` 인지 본다.
4. **도구별로 확인할 것.**

   | 도구 | 확인 | 어긋나면 |
   |---|---|---|
   | `realty_deals` (trade) | `deals[].deal_amount_manwon` 이 정수, `date` 가 `YYYY-M-D`, `total_count` > 0 | 상류 필드명이 바뀐 것이다 — `realty._item` 의 태그 이름을 실제 응답에 맞춘다 |
   | `realty_deals` (rent) | `deposit_manwon`·`monthly_rent_manwon` 이 온다 | 위와 같다. 전월세 서비스 활용신청을 빠뜨렸다면 `error_code: 20` 이다 |
   | 없는 달 조회 | `ok: true, count: 0` (오류가 아니다) | 상류의 NODATA 코드가 `03` 이 아닌 것이다 — `realty.EMPTY_CODE` 를 고친다 |
   | 잘못된 키 | `error_code: 30`, `error_kind: credential`, `apply_url` 이 온다 | 게이트웨이 응답 모양(`cmmMsgHeader`)이 다르다 |
   | `ecos_stats`(검색) | `tables[]` 가 오고 `scanned` 가 `TABLE_SCAN` 이하 | `list_total_count` 가 `TABLE_SCAN` 을 크게 넘으면 키워드가 훑는 범위 밖일 수 있다 — 상수를 올릴지 판단 |
   | `ecos_stats`(시계열) | `stat_code='901Y009', period='M'` 로 `rows[].value` 가 온다 | `ERROR-101` 이면 날짜 형식, `INFO-100` 이면 키 |
   | **`fx_rate`** | **`731Y003` 이 정말 일별 대원화환율인지**, `currency='미국달러'` 로 항목이 잡히는지, `available` 에 어떤 통화가 있는지 | **가장 검증이 덜 된 값이다.** 이 코드는 스킬의 2026-06-09 라이브 검증에서 왔을 뿐 이번에 확인하지 못했다. 틀렸다면 `ecos_stats` 로 「환율」을 검색해 맞는 표 코드를 찾아 `fx.STAT_CODE` 를 고친다 |

5. **누출 확인(라이브).** 일부러 틀린 키로 한 번 부른 뒤 **궤적 화면과 `hub-mcp` 로그**에 키가
   보이지 않는지 눈으로 본다. 단위 테스트는 가짜 키로만 재므로, 실제 상류가 오류 문장에 키를
   되돌려주는 경우는 여기서만 드러난다.
6. **한도.** 강의에서 공용 키를 여럿이 함께 쓰면 data.go.kr 은 `22`(일일 트래픽 초과), ECOS 는
   `ERROR-602` 를 먼저 만난다. 수강생 수 × 호출 빈도를 보고 개인 키 안내가 필요한지 판단한다.

## 6. 이번에 함께 고친 것 — 기존 테스트의 「비공개 탐침」

`fx` 를 공개로 돌리면서, `fx` 가 **비공개 도구의 표본**이던 테스트들(`tests/test_catalog_checks.py`
4곳, `tests/test_toolbox_scopes.py`)을 `fuel` 로 옮겼다. 판정의 뜻은 그대로다 — 「어댑터 없는 행을
DB 에서 켜면 `catalog.E001`」. 카탈로그를 고칠 때 이 탐침이 함께 움직여야 한다는 것이 드러났으니,
다음에 `fuel` 마저 공개하면 **탐침용 행이 없어진다.** 그때는 테스트 안에서 임시 행을 만드는 쪽으로
바꾸는 편이 낫다(계약 테스트의 `probe` 행이 이미 그 방식이다).

## 7. 관찰 · 남은 질문

- **`ecos_stats` 가 두 가지 일을 한다**(통계표 검색 / 시계열 조회). 슬러그 하나에 도구 하나라는
  불변식 때문이다. 모델이 인자로 모드를 고르는 형태라 설명이 길어졌는데, 도구가 더 늘면
  「한 카탈로그 행에 여러 MCP 도구」 를 허용할지 결정해야 한다(스코프는 행 단위로 두고 도구 이름만
  여럿). 지금 바꾸지 않은 이유는 그것이 스코프↔도구 1:1 이라는 **허브 뼈대의 변경**이기 때문이다.
- **통계표 검색이 클라이언트 필터**다. ECOS 의 `StatisticTableList` 에는 검색 파라미터가 없어
  앞쪽 1,000 건을 받아 거른다. `scanned`/`total` 을 함께 내 「없음」과 「훑은 범위 밖」을 가르게
  했지만, 실제 통계표 수가 1,000 을 크게 넘으면 상수를 올리거나 `ecos_stats` 에 `scan` 인자를
  여는 판단이 필요하다 — 라이브에서 `total` 을 보고 정한다.
- `fuel`(오피넷)은 그대로 비공개다. 오피넷은 별도 키 체계(무료, 신청 심의 있음)라 이번 범위 밖.
